# Backend architecture

This document describes the **Spring Boot URL shortener backend** as it is implemented: components, tools, how work is executed, request control flow, and the decisions behind that shape.

Related documents: [`0.Requirements-analysis.md`](0.Requirements-analysis.md) and [`openapi.json`](openapi.json).

---

## 1. Overview

The backend is a **single Spring Boot modular monolith**. One deployable JAR, copied into N identical pods, talks to one relational database. There is no cache, message broker, Spring Cloud Gateway, or second microservice. In a cluster the public edge is a **Kubernetes Ingress controller**, not an in-process API gateway.

```
 Client
          │  HTTPS :443
          ▼
 ┌────────────────────────────────────────────┐
 │ Ingress controller  (nginx / GKE / ALB / …)│  TLS, host routing, X-Forwarded-*
 │ Ingress: short.example.com  path /         │
 └────────────────────┬───────────────────────┘
                      │ ClusterIP :80
                      ▼
 ┌────────────────────────────────────────────┐
 │ Service  url-shortener                     │  load-balances to Ready pods
 └──────────┬─────────────────────┬───────────┘
            ▼                     ▼
     Pod / instance 1      Pod / instance 2     (Deployment replicas: 2)
     Spring Boot :8080     Spring Boot :8080
     own rate limiter      own rate limiter
     own click queue       own click queue
            └──────────┬──────────┘
                       │ JDBC
                       ▼
              PostgreSQL (managed, or optional in-cluster)
              short_link, click_event
```

Locally there is no Ingress: `mvnw spring-boot:run` binds one process to `:8080` on H2. The in-process path is the same: filters → interceptor → controller → service → JPA, with clicks handed to the bounded executor.

Four HTTP use cases sit on that stack:


| Use case  | HTTP                                 | What the backend does                                                                             |
| --------- | ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Create    | `POST /api/v1/short-urls`                 | Validate URL and optional expiry, allocate a unique 7-character code, persist a row, return `201` |
| Redirect  | `GET /{code}`                        | Look up the code, reject unknown (`404`) or expired (`410`), enqueue a click, return `302`        |
| Details   | `GET /api/v1/short-urls/{code}`           | Return URL, status, timestamps, all-time `totalClicks` (readable after expiry)                    |
| Analytics | `GET /api/v1/short-urls/{code}/analytics` | Bucket clicks in a time range and return top referrers                                            |


The only asynchronous work is **click recording**. Everything else is request-thread and transactional.

## 2. Cluster topology (Ingress, Service, instances)

Manifests live in `[k8s/](../k8s/)`. They deploy **this same JAR**; they do not add another application. There is no Spring Cloud Gateway, Zuul, or Kong in the repo. The “gateway” is the cluster’s **Ingress controller**.

### 2.1 Request path at the edge

1. DNS for `short.example.com` (placeholder in `k8s/ingress.yaml`) points at the Ingress controller’s load balancer.
2. The **Ingress controller** (nginx in the sample, `ingressClassName: nginx`) terminates TLS if a certificate is attached, matches host + `path: /`, and forwards to the Service. The annotation `nginx.ingress.kubernetes.io/proxy-body-size: 8k` matches the app’s 8 KB body cap. It sets `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-Forwarded-Host`.
3. The **Service** `url-shortener` is `ClusterIP` port 80 → pod port 8080. It is an internal load balancer only (kube-proxy / IPVS), not a public IP. Ready endpoints only: a pod whose readiness probe fails is taken out of rotation.
4. One of the **instances** (pods) handles the request on Tomcat `:8080`.

A cloud **API Gateway** (AWS API Gateway, Azure APIM, GCP API Gateway) is not required. Those products would sit *in front of* or *instead of* Ingress if you later wanted API keys, WAF, or usage plans. The app does not depend on them.

If a cluster has no Ingress, the Service can be changed to `type: LoadBalancer`. That skips host-based HTTP routing and TLS at Ingress; `APP_BASE_URL` must still be the public origin clients use.

### 2.2 Instances (replicas)


| Setting       | Value in `k8s/deployment.yaml`                            | Meaning                                                                                                                                             |
| ------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Replicas      | **2**                                                     | Two identical JVM processes. The Service spreads traffic (typically round-robin). No sticky sessions: the app is stateless except for the database. |
| Resources     | request 250m CPU / 512Mi; limit 1 CPU / 1Gi               | Heap is sized with `-XX:MaxRAMPercentage=75` in the image.                                                                                          |
| Startup probe | `/actuator/health/liveness`                               | Gives Flyway + JVM up to ~60 s before liveness starts failing.                                                                                      |
| Liveness      | `/actuator/health/liveness`                               | Restart the container if the process is wedged. Does not include the database.                                                                      |
| Readiness     | `/actuator/health/readiness`                              | Stop sending traffic if PostgreSQL is down.                                                                                                         |
| Security      | non-root uid 10001, read-only root, drop all capabilities | `/tmp` is an `emptyDir`.                                                                                                                            |
| Shutdown      | `preStop` sleep 5 s; `terminationGracePeriodSeconds: 40`  | Lets the Service drop the endpoint, then drain Tomcat and the click queue (app shutdown phase 20 s).                                                |


There is **no HPA** in the repo. Scale by changing `replicas` (or adding an HPA later). Each new pod is another instance with its own memory, Hikari pool, rate limiter, and click queue.

Flyway runs on every start. Concurrent migrators take Flyway’s advisory lock; one applies, the others wait, then Hibernate validates.

### 2.3 What is per instance vs shared


| State                        | Where                    | Consequence of 2 (or N) instances                                                                                                                                    |
| ---------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `short_link` / `click_event` | PostgreSQL (shared)      | All pods see the same links and counts. `click_count` increments are atomic in SQL, so concurrent clicks across pods do not lose updates.                            |
| Hikari pool                  | Per pod, default 10      | N pods ⇒ up to `N × 10` connections. Size the database and `DB_POOL_SIZE` together.                                                                                  |
| Rate limiter                 | In-memory per pod        | Limits are **not** cluster-wide. Two pods ≈ 2× the create / miss / analytics budget for the same client IP. A shared store (Redis) would be needed for a global cap. |
| Click queue                  | In-memory per pod (1000) | Two independent buffers. A pod that is killed loses only *its* queued clicks. Cluster burst capacity ≈ `N × 1000`.                                                   |
| `Clock`, code generator      | Per process              | Codes stay unique because of the DB constraint, not because pods coordinate.                                                                                         |


Prod sets `server.forward-headers-strategy: framework` so `getRemoteAddr()` is the client IP from the Ingress hop, not the controller’s pod IP. The Ingress must be the only untrusted-to-trusted boundary (do not let clients spoof `X-Forwarded-For` past it).

### 2.4 Database in the cluster

Prefer a **managed** PostgreSQL (Cloud SQL, RDS, Azure Database). Point `DB_URL` at it in the Secret.

`k8s/postgres.yaml` is an optional single-replica in-cluster database for a demo cluster only. It is not HA. If you use it:

`DB_URL=jdbc:postgresql://postgres.url-shortener.svc.cluster.local:5432/urlshortener`

### 2.5 Config at deploy time


| Source    | Keys                                                                                                                                                           |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ConfigMap | `SPRING_PROFILES_ACTIVE=prod`, `APP_BASE_URL` (must match the Ingress host, e.g. `https://short.example.com`), `DB_POOL_SIZE`, optional `CORS_ALLOWED_ORIGINS` |
| Secret    | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`                                                                                                                         |


`APP_BASE_URL` is how `shortUrl` is built in JSON. If it disagrees with the Ingress host, created links point at the wrong origin.

## 4. Components

Root package: `com.bharath.projects.urlshortener`. Controllers speak HTTP and DTOs. Services own rules. Repositories own SQL/JPA. Entities never leave the service layer.

### 4.1 Package map

```
com.bharath.projects.urlshortener
├── UrlShortenerApplication          entry point, component scan
├── controller/
│   ├── LinkController               /api/v1/short-urls  (create, details, analytics)
│   └── RedirectController           /{code}        (302)
├── service/
│   ├── LinkService / ClickService   interfaces
│   └── impl/
│       ├── LinkServiceImpl          validate, allocate code, resolve, details
│       ├── ClickServiceImpl         enqueue click, aggregate analytics
│       └── ClickWriter              one transaction: insert event + increment count
├── repository/
│   ├── ShortLinkRepository          findByCode, incrementClickCount
│   └── ClickEventRepository         streamClickTimes, topReferrers
├── entity/                          ShortLink, ClickEvent
├── dto/                             request/response records; ApiError is docs-only
├── exception/                       domain exceptions + GlobalExceptionHandler
├── filter/                          correlation id, body size, security headers, rate limit
├── config/                          properties, Clock, click executor, CORS, OpenAPI
└── util/                            UrlValidator, ShortCodeGenerator/Format, RateLimiter
```

### 4.2 HTTP edge (inside the JVM)

`**LinkController**` — versioned JSON API. Create returns `201` plus `Location: /api/v1/short-urls/{code}`. Details and analytics stay available after expiry.

`**RedirectController**` — public short URL. Always `302` and `Cache-Control: no-store`. `HEAD` is handled by the same `@GetMapping` (Spring default) but is **not** recorded as a click, so link checkers and previews do not inflate counts.

**Filters** (servlet, all requests):


| Filter                   | Role                                                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CorrelationIdFilter`    | Accepts `X-Correlation-Id` only if it matches `[A-Za-z0-9._-]{1,64}`; otherwise generates one. Puts it in the MDC as `traceId` and echoes it on the response. |
| `RequestSizeLimitFilter` | Rejects bodies over 8 KB with `413 PAYLOAD_TOO_LARGE` before Jackson parses them.                                                                             |
| `SecurityHeadersFilter`  | `X-Content-Type-Options`, `X-Frame-Options`, CSP. Frame/CSP skipped on `/h2-console` and `/swagger-ui` so those tools still work locally.                     |


`**RateLimitInterceptor**` — not a filter. It runs after CORS is applied so a `429` still includes CORS headers. Only `LinkController` and `RedirectController` are limited. The key is `request.getRemoteAddr()` (the real client IP only after Ingress forwards `X-Forwarded-For` and prod’s `forward-headers-strategy: framework` is applied). Limits are per instance; see §2.3.

Three independent token buckets per IP (defaults; `local` uses 300 for all three):


| Limit     | Default  | Applied to                                                                                                                                                      |
| --------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create    | 30 / min | `POST /api/v1/short-urls`                                                                                                                                            |
| Analytics | 30 / min | `GET .../analytics` (the expensive read)                                                                                                                        |
| Miss      | 60 / min | Unknown-code lookups (anti-enumeration). A miss is recorded when `LinkNotFoundException` is handled. Successful redirects are **not** create/analytics-limited. |


`**GlobalExceptionHandler**` — one RFC 7807 `application/problem+json` envelope: `type`, `title`, `status`, `detail`, `code`, `traceId`. Stack traces and SQL never leave the process. On `GET /{code}`, `Accept: text/html` gets a small static HTML page instead of JSON.


| `code`                                                                                         | HTTP | When                                             |
| ---------------------------------------------------------------------------------------------- | ---- | ------------------------------------------------ |
| `INVALID_URL` / `INVALID_EXPIRY` / `INVALID_RANGE` / `INVALID_PARAMETER` / `MALFORMED_REQUEST` | 400  | Bad input                                        |
| `LINK_NOT_FOUND`                                                                               | 404  | Unknown or malformed code                        |
| `LINK_EXPIRED`                                                                                 | 410  | Redirect of an expired link (details still work) |
| `PAYLOAD_TOO_LARGE`                                                                            | 413  | Body > 8 KB                                      |
| `RATE_LIMITED`                                                                                 | 429  | Plus `Retry-After`                               |
| `DATABASE_UNAVAILABLE` / `CODE_ALLOCATION_FAILED`                                              | 503  | Plus `Retry-After`                               |
| `DATABASE_ERROR` / `INTERNAL_ERROR`                                                            | 500  | Logged, generic body                             |


### 4.3 Domain services

`**LinkServiceImpl**`

- Validates and normalizes the URL (`UrlValidator`).
- Validates optional expiry: must be strictly in the future and at most 5 years ahead (`Clock`).
- Allocates a code with `ShortCodeGenerator` (7-char base62, `SecureRandom`) and `saveAndFlush`. `**create` is not `@Transactional**`: a unique-constraint violation marks a PostgreSQL transaction rollback-only, so each insert must be its own transaction for the retry loop (up to 5) to work.
- `resolve` / `getDetails`: reject malformed codes without a database hit; expiry is `now >= expiresAt` at request time (no scheduler).

`**ClickServiceImpl**`

- Builds the `ClickEvent` on the **request thread** (timestamp, sanitized referrer and user agent) and submits `persist` to the click executor.
- Queue full or executor shut down: log a warning and return. The redirect is never failed.
- Write failure on the worker: log an error and swallow it.
- Analytics: default window last 30 days, max 366 days, half-open `[from, to)`. Streams click timestamps and buckets them in Java (UTC) so H2 and PostgreSQL match. Series are sparse. Top 10 referrers; null referrers are excluded.

`**ClickWriter**` — separate bean so `@Transactional` is applied through a Spring proxy. One transaction: insert `click_event` and `UPDATE short_link SET click_count = click_count + 1`. If the increment updates 0 rows, it throws and the insert rolls back. Counter and event log cannot diverge.

### 4.4 Persistence

```
short_link
  id PK
  code UNIQUE          -- lookup index for redirects
  original_url         -- max 2048
  created_at, expires_at (timestamptz, UTC)
  click_count          -- denormalized, default 0

click_event
  id PK
  short_link_id FK ON DELETE CASCADE
  clicked_at
  referrer, user_agent -- nullable, max 512
  -- no IP column
  INDEX (short_link_id, clicked_at)
```

Schema: `src/main/resources/db/migration/V1__create_short_link_and_click_event.sql`.

### 4.5 Click executor

`ClickExecutorConfig` exposes a `ThreadPoolTaskExecutor` named `clickExecutor`:


| Setting         | Default                              | Meaning                                                                                                       |
| --------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| core / max pool | 2 / 4                                | Workers that run `ClickWriter`                                                                                |
| queue capacity  | 1000                                 | Pending clicks in memory                                                                                      |
| rejection       | `AbortPolicy`                        | `execute` throws; caller logs and drops. **Not** `CallerRunsPolicy` (that would write on the request thread). |
| shutdown        | wait up to 10 s                      | Drain queued clicks                                                                                           |
| destroy order   | `@DependsOn("entityManagerFactory")` | Executor is stopped *before* JPA/pool, so drain can still write                                               |


This is an in-JVM waiting room, not Kafka or Redis. Each instance has its own queue. See §5.2.

### 4.6 Supporting utilities

- `**UrlValidator**` — `http`/`https` only, host required, no userinfo, ASCII, max 2048. Prod rejects localhost, private/loopback/link-local/metadata addresses and numeric tricks. The server never fetches the target and does not do DNS during validation (no SSRF surface).
- `**ShortCodeGenerator` / `ShortCodeFormat**` — 7-character `[0-9A-Za-z]`. Malformed codes are treated as not found.
- `**RateLimiter**` — in-memory token buckets; idle buckets are purged so the map cannot grow without bound.
- `**Clock` bean** — UTC “now” for create, expiry, and click time; tests substitute a fixed clock.

### 4.7 What is not in the application

No Redis, no Caffeine, no outbox table, no second JVM dedicated to clicks, no auth/ownership layer, and **no in-app API gateway**. Ingress + Service are cluster infrastructure in front of N copies of this JAR.

## 5. Execution approach

### 5.1 Request thread (synchronous path)

Tomcat handles HTTP. After filters and the rate-limit interceptor, the controller calls a service on the **same thread**.

- **Create / details / analytics** — the response is sent only after the database work finishes (or an exception is mapped).
- **Redirect** — the response is sent after `resolve` and after `recordClick` *submits* work. It does not wait for `ClickWriter`.

Hikari in prod: pool size 10 (override `DB_POOL_SIZE`), connection timeout 3 s so a stuck database becomes `503` instead of hanging the request.

### 5.2 Click recording (asynchronous path)

```
request thread                         worker thread (click-*)
──────────────                         ──────────────────────
build ClickEvent (now, headers)
executor.execute(persist)
   └─ queued (max 1000) ─────────────► writer.write(event)
return 302                               INSERT + increment
                                         catch → log
```

Why this is explicit `Executor.execute` rather than `@Async`:

- The same bounded pool is required either way; `@Async` does not create it.
- Overflow must be caught on the **submitter** so a full queue cannot turn into a 500 on the redirect.
- The event must be built on the request thread so `clicked_at` is the redirect instant.
- `@Async` on a private method in the same class is a no-op (Spring proxy). The current call is obvious and unit-testable by injecting a fake `Executor`.

Clicks are **best-effort / eventually consistent**. Overflow and a hard kill lose clicks still in the queue. Graceful shutdown drains for up to 10 s (process shutdown phase 20 s; Kubernetes `terminationGracePeriodSeconds` is 40).

Capacity (order of magnitude): two workers at ~5 ms per write drain about **400 clicks/s**. The queue of 1000 is a burst buffer. Typical traffic never fills it. A viral link (row-lock contention on `click_count`) or a write stall of tens of seconds can fill it; extra clicks are dropped and logged. Successful redirects are not rate-limited, so that spike is possible.

### 5.3 Transactions


| Operation                     | Transaction boundary                                        |
| ----------------------------- | ----------------------------------------------------------- |
| Create insert attempt         | Repository `saveAndFlush` (each retry is a new transaction) |
| Details / resolve / analytics | `@Transactional(readOnly = true)` on the service method     |
| Click persist                 | `@Transactional` on `ClickWriter.write` only                |


Analytics streams `clicked_at` values and must close the stream inside the read-only transaction.

### 5.4 Process lifecycle in production

1. Container starts with `SPRING_PROFILES_ACTIVE=prod`.
2. Flyway applies pending migrations; Hibernate validates the schema.
3. Kubernetes **startup / liveness** → `/actuator/health/liveness`; **readiness** → `/actuator/health/readiness` (not ready if the database is down).
4. Ingress terminates TLS and forwards `X-Forwarded-*`; the app uses those for the client IP used in rate limits.
5. On SIGTERM: `preStop` sleep, then graceful Tomcat shutdown, then the click executor drains, then the pool closes.

`APP_BASE_URL` is the public origin used to build `shortUrl` in JSON. It must match the Ingress host.

## 6. Control flow

### 6.1 Create (`POST /api/v1/short-urls`)

```
RequestSizeLimitFilter
    │  body > 8 KB → 413
    ▼
RateLimitInterceptor.tryAcquireCreate(ip)
    │  denied → 429
    ▼
LinkController.create
    ▼
LinkServiceImpl.create          ← not class-transactional
    UrlValidator.validateAndNormalize
    validateExpiry (future, ≤ 5 years)
    loop up to max-collision-retries:
        generate code
        saveAndFlush
        unique violation on that code → retry
        other integrity error → rethrow
    exhausted → CodeGenerationException → 503
    ▼
201 + Location + LinkResponse
```

Each create gets a **new** code. The same long URL is not deduplicated.

### 6.2 Redirect (`GET /{code}`)

```
RateLimitInterceptor.checkMiss(ip)     ← only trips after many 404s
    ▼
RedirectController
    ▼
LinkServiceImpl.resolve
    malformed code → 404 (no SQL)
    missing row    → 404 (handler also recordMiss)
    now >= expiresAt → 410
    ▼
if method != HEAD:
    ClickServiceImpl.recordClick
        build event now
        execute(persist) or catch → log drop
    ▼
302 Location=<originalUrl>  Cache-Control=no-store
    │
    └─ later: ClickWriter  INSERT click_event + increment click_count
```

HEAD still 302s; it is not a click.

### 6.3 Details (`GET /api/v1/short-urls/{code}`)

Same lookup as resolve, but expiry becomes `status: EXPIRED` instead of `410`. `totalClicks` is the denormalized counter (may lag a few milliseconds behind a just-served redirect).

### 6.4 Analytics (`GET /api/v1/short-urls/{code}/analytics`)

```
RateLimitInterceptor
    tryAcquireAnalytics then checkMiss
    ▼
ClickServiceImpl.getAnalytics
    default to / from / DAY; reject empty, reversed, or > 366-day range
    find link or 404
    stream clicked_at in [from, to) → bucket in Java (UTC)
    top 10 referrers (non-null)
    ▼
200 AnalyticsResponse
    totalClicks     all-time counter
    clicksInRange   sum of series
    series[]        non-empty UTC buckets only
    topReferrers[]
```

Bucketing is done in Java because `date_trunc` / session time zones differ between H2 and PostgreSQL.

### 6.5 Database failure

Transient / connection failures → `503 DATABASE_UNAVAILABLE` + `Retry-After: 5`. Other `DataAccessException` → `500 DATABASE_ERROR`. Health readiness goes down when the DataSource is unreachable; the process does not need a restart to recover.

## 7. Key decisions


| Decision            | Choice                                                   | Why                                                                                                            |
| ------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Shape               | One app, one database, N identical pods                  | Brief forbade extra *product* services. The unit of deploy is the JAR. Scale by replica count.                 |
| Redirect status     | **302** + `no-store`                                     | 301 is cached; later visits would skip the server, so analytics and expiry would be wrong.                     |
| Code format         | 7-char base62, `SecureRandom`                            | ~3.5×10¹² codes; not enumerable by incrementing. Uniqueness is a **DB unique constraint**, not only app logic. |
| Redis / Caffeine in front of `resolve` | Not added | Analytics is not called frequently. If it is later wired into live stats (or similar high-frequency reads), a cache would keep those lookups very fast. |
| External queue | In-process bounded executor | Click recording is a simple database write today. If more work is added around each click, or the in-process bounded queue is no longer enough, introduce a message queue or Kafka. |
| Collision handling  | Bounded retry (5), `create` not one big `@Transactional` | PostgreSQL aborts the transaction on unique violation; retries need a clean transaction each time.             |
| `@Async` for clicks | Not used; submit to the bounded executor                 | Same pool would still be required; hides overflow and timestamp capture; proxy/self-invocation pitfalls.       |

## 8. How the pieces fit on a single redirect

End-to-end for a client hitting a live short URL in the cluster:

1. DNS → Ingress controller (TLS, host `short.example.com`, path `/`).
2. Ingress forwards to Service `url-shortener` (ClusterIP). The Service picks a **Ready** instance (one of the two pods).
3. That JVM: correlation id is bound; security headers go out on the response.
4. That instance’s rate limiter allows the request (successful codes do not consume the create/analytics buckets).
5. `RedirectController` calls `resolve`: format check, indexed `findByCode`, expiry vs `Clock`.
6. On GET (not HEAD), `recordClick` snapshots time and headers and offers the event to **this pod’s** queue of 1000.
7. Controller returns `302` immediately.
8. A `click-*` thread on the **same** pod inserts the event and increments `click_count` in PostgreSQL.
9. A later details or analytics call may land on **either** pod; both read the shared tables.

Locally, steps 1–2 collapse to `localhost:8080` and a single instance.

That split — **synchronous correctness on the redirect decision, asynchronous best-effort on the write** — is the center of the backend design. The cluster only multiplies instances in front of the same database.
