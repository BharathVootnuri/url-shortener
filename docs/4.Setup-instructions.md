# Setup instructions

How to run the URL shortener **backend** and **frontend** on a laptop, and how to run the backend against PostgreSQL, in Docker, and in Kubernetes.

Related: [`1.Architecture.md`](1.Architecture.md), [`4.Testing-approach.md`](4.Testing-approach.md), [`k8s/README.md`](../k8s/README.md), [`openapi.json`](openapi.json).

---

## Prerequisites

| What | Version | Notes |
| --- | --- | --- |
| JDK | 21 | Required for the backend. The Maven wrapper downloads Maven itself. |
| Maven Wrapper | in-repo | Windows: `.\mvnw.cmd` · macOS/Linux: `./mvnw` |

From the repository root (`url-shortener/`).

## 1. Local (H2, no extra services)

The default profile is `local`: in-memory H2 in PostgreSQL mode. Flyway creates the schema on startup. Data is lost when the process stops.

```powershell
.\mvnw.cmd spring-boot:run
```

```bash
./mvnw spring-boot:run
```

The API listens on **http://localhost:8080**.

| URL | What |
| --- | --- |
| http://localhost:8080/swagger-ui.html | Swagger UI (`local` only) |
| http://localhost:8080/v3/api-docs | OpenAPI JSON (`local` only) |
| http://localhost:8080/actuator/health | Health |
| http://localhost:8080/h2-console | H2 console. JDBC URL `jdbc:h2:mem:urlshortener`, user `sa`, empty password |

Private/localhost target URLs are allowed in this profile so redirects can be tested.

### Smoke-test the API

```bash
curl -s -X POST http://localhost:8080/api/v1/short-urls \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/docs?page=1","expiresAt":"2030-01-01T00:00:00Z"}'

# replace <code> with the code from the response
curl -i http://localhost:8080/<code>
curl -s http://localhost:8080/api/v1/short-urls/<code>
curl -s "http://localhost:8080/api/v1/short-urls/<code>/analytics?granularity=HOUR"
```

PowerShell:

```powershell
$link = Invoke-RestMethod -Method Post http://localhost:8080/api/v1/short-urls `
  -ContentType application/json `
  -Body '{"url":"https://example.com/docs?page=1"}'
$link
curl.exe -i $link.shortUrl
Invoke-RestMethod http://localhost:8080/api/v1/short-urls/$($link.code)
```

Clicks are written asynchronously. Wait a moment before reading details or analytics if the count is still zero.

## 2. Frontend (local run / test)

The Angular UI in `frontend/` is a thin harness for the backend. Start the backend from section 1 first. The `local` profile already allows CORS from `http://localhost:4200`.

```powershell
cd frontend
npm install
npm start
```

```bash
cd frontend
npm install
npm start
```

Open **http://localhost:4200**. Use it to create a link, follow the short URL, and read details / analytics. That is the local test of the UI — there are no automated frontend tests.

The committed API contract is [`openapi.json`](openapi.json). Swagger UI at http://localhost:8080/swagger-ui.html is another way to exercise the same endpoints.

## 4. PostgreSQL (`prod` profile)

Create an empty database (example name `urlshortener`). Flyway applies `src/main/resources/db/migration` on first start. Hibernate does not migrate (`ddl-auto: validate`).

| Variable | Required | Example |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | yes | `prod` |
| `DB_URL` | yes | `jdbc:postgresql://localhost:5432/urlshortener` |
| `DB_USERNAME` | yes | `urlshortener` |
| `DB_PASSWORD` | yes | |
| `APP_BASE_URL` | yes | `http://localhost:8080` (used to build `shortUrl`) |
| `DB_POOL_SIZE` | no | `10` |
| `CORS_ALLOWED_ORIGINS` | no | comma-separated origins; wildcards are refused at startup |

```powershell
.\mvnw.cmd -DskipTests package
$env:SPRING_PROFILES_ACTIVE = "prod"
$env:DB_URL = "jdbc:postgresql://localhost:5432/urlshortener"
$env:DB_USERNAME = "urlshortener"
$env:DB_PASSWORD = "..."
$env:APP_BASE_URL = "http://localhost:8080"
java -jar target\url-shortener.jar
```

```bash
./mvnw -DskipTests package
export SPRING_PROFILES_ACTIVE=prod
export DB_URL=jdbc:postgresql://localhost:5432/urlshortener
export DB_USERNAME=urlshortener
export DB_PASSWORD=...
export APP_BASE_URL=http://localhost:8080
java -jar target/url-shortener.jar
```

In `prod`, Swagger UI, `/v3/api-docs`, the H2 console, and actuator endpoints other than health (and the k8s probe paths) are off. Localhost and private-network target URLs are rejected.

**Always set `SPRING_PROFILES_ACTIVE=prod` when using PostgreSQL.** The default profile is `local`. If it is unset, the process starts on in-memory H2.

## 5. Docker

The image is the backend only and defaults to `SPRING_PROFILES_ACTIVE=prod`.

```bash
docker build -t url-shortener:0.0.1 .
docker run --rm -p 8080:8080 \
  -e DB_URL=jdbc:postgresql://host.docker.internal:5432/urlshortener \
  -e DB_USERNAME=urlshortener \
  -e DB_PASSWORD=... \
  -e APP_BASE_URL=http://localhost:8080 \
  url-shortener:0.0.1
```

`host.docker.internal` reaches PostgreSQL on the host from Docker Desktop. On Linux you may need `--add-host=host.docker.internal:host-gateway` or the database container’s network name.

Push to a registry before deploying to a cluster:

```bash
docker tag url-shortener:0.0.1 YOUR_REGISTRY/url-shortener:0.0.1
docker push YOUR_REGISTRY/url-shortener:0.0.1
```

## 6. Kubernetes

Manifests are in [`k8s/`](../k8s/). See [`k8s/README.md`](../k8s/README.md) for the full notes.

1. Set `images.newName` in `k8s/kustomization.yaml` to `YOUR_REGISTRY/url-shortener`.
2. Set `APP_BASE_URL` (and the Ingress host) in `k8s/configmap.yaml` to the public origin, for example `https://short.example.com`.
3. Set `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` in `k8s/secret.yaml` (do not commit real passwords). Prefer a managed PostgreSQL.
4. Apply:

```bash
kubectl apply -k k8s
# optional demo database in the cluster:
# kubectl apply -f k8s/postgres.yaml
```

If you use the demo Postgres, set:

```
DB_URL=jdbc:postgresql://postgres.url-shortener.svc.cluster.local:5432/urlshortener
```

Check:

```bash
kubectl -n url-shortener get pods,svc,ingress
kubectl -n url-shortener logs deploy/url-shortener
curl -s https://short.example.com/actuator/health
```

| Probe | Path |
| --- | --- |
| Startup / liveness | `/actuator/health/liveness` |
| Readiness | `/actuator/health/readiness` (fails if PostgreSQL is down) |

The Deployment runs **2** replicas. Rate limits and the click queue are per pod.

## 7. Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| App starts but data vanishes after restart | Running the `local` profile (H2). Set `SPRING_PROFILES_ACTIVE=prod`. |
| Startup fails on missing `DB_URL` | `prod` is on but the database env vars are not set. |
| `503 DATABASE_UNAVAILABLE` | PostgreSQL unreachable or credentials wrong. Check `DB_URL` and network/firewall. |
| Health is `DOWN` | Same as above; readiness will keep the pod out of the Service. |
| `400 INVALID_URL` for `http://localhost/...` | `prod` rejects private/loopback hosts. Use `local` or a public http(s) URL. |
| `429 RATE_LIMITED` | Create / miss / analytics buckets (30 / 60 / 30 per minute in prod). Wait for `Retry-After`. |
| Click count still 0 right after a redirect | Async write; retry details/analytics after a short wait. |
| `shortUrl` host is wrong | `APP_BASE_URL` does not match how clients reach the app (Ingress host). |
| UI at :4200 cannot reach the API | Backend is not running, or you are not on the `local` profile (CORS is only open to `http://localhost:4200` there). |
