# Testing approach, limitations, and trade-offs

## How to run

```powershell
.\mvnw.cmd verify
```

```bash
./mvnw verify
```

That runs the full suite and then the coverage gate.

## Scale of the suite

| | Count |
| --- | --- |
| Automated tests | **282** (JUnit 5; includes parameterized cases) |
| Test classes | 21 under `src/test/java` |
| Coverage gate | 80% line coverage on `service.impl` and `util` |
| Current coverage | about **99%** (`service.impl`) and **97%** (`util`) |

Most tests are unit tests (no Spring). The rest are `@SpringBootTest` + MockMvc against H2 with the real Flyway migration.

## Approach

- **Unit tests** cover URL validation, short-code format, rate limits, expiry (`Clock`), and click/create logic. A fake `Executor` is injected so async clicks do not need `sleep`.
- **Integration tests** cover the HTTP API: create, redirect, details, analytics, and error bodies (`code`, `traceId`).
- **Hard cases** include code collisions, 60 concurrent redirects, a full click queue (redirect stays `302`), and a database outage (health `DOWN`, API `503`, then recovery).
- **Contract test** fails if the live OpenAPI spec differs from `docs/openapi.json`.
- Async writes are awaited with Awaitility, not fixed delays.

Acceptance criteria for Features 1–6 each have an automated test. See [`0.Requirements-analysis.md`](0.Requirements-analysis.md) Part K.

## Limitations

- Redirect latency (p95) is not load-tested. The path is one indexed lookup plus a non-blocking click hand-off.
- Tests run in a single process. They do not cover multiple replicas or a shared rate-limit store.
- Analytics is tested on small ranges, not millions of click rows.
- `click_event` is not purged or partitioned; growth is accepted at this scale.
- Click overflow and write failures are logged; there is no metric assertion for them.

## Trade-offs

| Choice | Trade-off |
| --- | --- |
| Async clicks, drop when the queue is full | Redirect stays fast and succeeds. A few clicks can be lost. |
| H2 (PostgreSQL mode) for the suite | Fast, no extra services. Same Flyway SQL as prod. |
| In-memory rate limiter | Simple. Per instance; resets on restart. |
| Explicit executor, not `@Async` | Overflow and click time stay on the request thread, and are easy to unit-test. |
| `click_count` updated with the event row | Details stay cheap; a very hot link can contend on that row. |
| Coverage gate on service/util only | Rules are guarded. Thin controllers are covered by MockMvc instead. |
| Committed OpenAPI file | Accidental contract changes fail the build. Intentional ones need a deliberate regenerate. |
